# Project Structure

## Directory Layout

```
stability/
├── .git/                      # Git version control
├── .gitignore                 # Git ignore rules
├── claude.md                  # LLM behavioral guidelines
├── opencode.json              # OpenCode framework configuration
├── README.md                  # Brief project description
├── fonts/                     # Font assets (if any)
├── skills/                    # Core skill implementations
│   ├── deploy-cel-skills.sh  # Skill deployment script
│   ├── cel.git.sync/         # Git synchronization skill
│   ├── cel.screen.read/      # Screenshot analysis skill
│   ├── cel.src.review/       # Documentation review skill
│   ├── cel.wiki.init/        # Wiki initialization skill
│   ├── cel.wiki.read/        # Wiki context reading skill
│   ├── cel.wiki.simplify/    # Wiki simplification skill
│   └── cel.wiki.write/       # Wiki documentation generation skill
└── wiki/                      # Generated documentation (created by cel.wiki.init)
    ├── overview.md           # Project overview
    ├── structure.md          # This file
    ├── setup.md              # Installation and setup guide
    ├── development.md        # Development workflow
    ├── skills.md             # Skill reference documentation
    └── raw/                  # Static assets (PDFs, transcripts, exports)
```

## Directory Descriptions

### `skills/` - Core Skill Implementations
Contains all CEL (Coding Agent Skills) in a modular, reusable format. Each skill is a self-contained directory with:
- **SKILL.md**: Comprehensive skill documentation with YAML frontmatter metadata
- Skill-specific configuration or helper files as needed

**Subdirectories:**
- **cel.git.sync/** - Automated git workflow management
- **cel.screen.read/** - Visual debugging and screenshot analysis
- **cel.src.review/** - Documentation quality assurance and consistency checking
- **cel.wiki.init/** - Wiki folder structure initialization
- **cel.wiki.read/** - Project context analysis and persistence
- **cel.wiki.simplify/** - Wiki consolidation and optimization
- **cel.wiki.write/** - Baseline documentation generation

### `wiki/` - Project Documentation
Generated and managed documentation directory containing:
- **Markdown files**: Organized project documentation
- **raw/**: Static assets (PDFs, transcripts, images, exports)
- **.cel/context.md**: Persistent project context cache (generated by cel.wiki.read)

### Root-Level Configuration Files

| File | Purpose |
|------|---------|
| **claude.md** | Behavioral guidelines for LLM-based coding (simplicity, surgical changes, goal-driven execution) |
| **opencode.json** | Framework configuration for OpenCode.ai integration with model settings and formatters |
| **README.md** | Brief one-line project description |
| **.gitignore** | Git ignore patterns for version control |
| **fonts/** | Font assets used in the project |

## File Organization Conventions

### Skill Directories
Each skill follows the naming convention `cel.<skill-name>/` and contains:
```
cel.example-skill/
└── SKILL.md                   # Full skill documentation
```

**SKILL.md Format:**
```yaml
---
name: cel.example-skill
description: "Brief skill description. Usage: `/cel.example-skill`"
---

# Full Skill Title

## Documentation content...
```

### Documentation Files
Wiki documentation uses single-word, lowercase filenames:
- `overview.md` - Project overview and architecture
- `structure.md` - Directory layout and organization (this file)
- `setup.md` - Installation and environment setup
- `development.md` - Development workflow and processes
- `skills.md` - Detailed skill reference and usage
- `troubleshoot.md` - Common issues and solutions (if needed)

### Static Assets
Assets stored in `wiki/raw/` organized by type:
```
wiki/raw/
├── PDFs/                      # PDF documents
├── Transcripts/               # Text transcripts and transcripts
├── Exports/                   # Exported documentation
└── Images/                    # Screenshots and diagrams
```

## Key Files and Their Roles

| File | Role | Owner |
|------|------|-------|
| `skills/deploy-cel-skills.sh` | Automated deployment to local environments | DevOps/Automation |
| `claude.md` | Behavioral guidelines for AI-assisted coding | Documentation |
| `opencode.json` | Framework configuration | Configuration |

## Important Patterns

### Skill Metadata
Each skill's SKILL.md includes YAML frontmatter with:
```yaml
---
name: cel.skill-name
description: "One-line description and usage"
---
```

### Cross-Platform Paths
The deployment script (`deploy-cel-skills.sh`) handles:
- WSL detection and dual deployment (WSL + Windows)
- macOS, Linux, and Linux environments
- Platform-specific home directory resolution

### Documentation Structure
All wiki markdown files are stored flat in `wiki/` directory (not nested), with cross-references using relative links.

## Dependency Tree

```
cel.wiki.write (this skill)
  ├→ cel.wiki.init (creates wiki structure)
  ├→ cel.wiki.read (loads project context)
  └→ cel.wiki.simplify (cleans up generated docs)

cel.git.sync
  └→ (uses git CLI directly)

deploy-cel-skills.sh
  └→ (all cel.* skills)
```
